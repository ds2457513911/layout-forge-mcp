封装自动生成工具 —— 使用说明与效果汇报

用途：给它一份规格书 PDF，自动算出尺寸并在 Allegro 里把封装画出来，产出可直接使用的封装文件。 面向汇报与使用；每一步的失败处理、排障、改代码的方法见 docs\SOP-封装生成作业流程.md。

一、工具背景

1.1 以前怎么做

工程师在 Allegro 里手工建封装：查规格书找尺寸 → 算焊盘大小 → 算每个脚的坐标 → 一个焊盘一个焊盘建、摆、改 padstack → 画丝印、画本体、画占位框 → 编译 → 再自查一遍。

三个老问题：

问题表现
慢一个器件几十步手工操作，引脚越多越久
易错坐标算错、padstack 尺寸填错，肉眼很难发现
难复用换个人做，尺寸口径、命名习惯都不一样

1.2 现在怎么做

把规格书 PDF 放好，在对话框里说一句话就行：

帮我根据这份规格书建立封装：<规格书路径或文件夹>

剩下的事 AI 自己做：定位尺寸页 → 读参数 → 算几何 → 驱动 Allegro 画出封装 → 编译出成品 → 归档。 日常使用不需要敲任何命令。

输入：一份规格书 PDF； 输出：封装三件套（.dra 图纸 / .psm 成品 / .pad 焊盘），可直接进检查工具验收。

1.3 和"封装自动检查"怎么接力

公司里还有一个"封装自动检查"工具（比对规格书与封装，出判定报告）。两个工具是一前一后的关系：

规格书 ──▶【自动生成】──▶ 封装文件 ──▶【自动检查】──▶ 判定报告
                              ▲                            │
                              └──────── 不合格？改了再查 ─────┘

生成工具负责"做出来"，检查工具负责"验一遍"。生成的封装不需要人工先过目，可以直接丢给检查工具验收。

二、工具效果

说明：以下数据均来自实际生成记录，出处标在表下方；没有实测过的数字不写。

2.1 案例器件

3S48000163 无源晶振（SMD，本体 3.2 × 2.5 mm，4 个焊盘）——库里有人工做的标准件可以逐值对照。

2.2 产出了什么

一个归档文件夹，里面封装三件套 + 规格书 + 校验记录：

<规格书所在目录>\NB_XTAL4_3D2X2D5X0D7\
├── NB_XTAL4_3D2X2D5X0D7.dra     ← 封装图纸（可编辑）
├── nb_xtal4_3d2x2d5x0d7.psm     ← 成品（画板子时真正调用的）
├── r1d4x1d2.pad                 ← 焊盘定义
├── <规格书>.pdf                 ← 同型号规格书，跟封装放在一起
└── README.md                    ← 清单 + 校验值 + 尺寸出处

2.3 和人工做的对比（这是最硬的一条）

该器件库里有人工做的标准件，把工具算出来的几何和它逐值对拍：

对拍项结果
几何参数逐值对拍（焊盘尺寸 / 坐标 / 本体 / 占位框 / 位号）164 / 164 全部对上

2.4 质量检查结论

生成的封装可以直接交给检查工具（19 项自动检查）验收。

说明：目前生成和检查是两个工具分开跑，还没有自动串成一条流水线。

三、操作方法

每步统一两件事：做什么 / 看到什么就算成功。

部署方式：当前处于本地测试阶段，服务装在使用者自己的电脑上； 后续会安排服务器部署，改为远程调用服务——使用方式不变。

3.1 现在的装法：只在作者本机手工配好了

现状：这台工具目前没有做迁移化重构，只在作者本机手工配好了，别人要用得手工照抄一遍：

要配的东西现在的实际情况
MCP 服务名 layout-forge-mcp，配置里写死指向作者本机的项目路径（...\Layout\layout-forge-mcp）
配套技能allegro-skillbridge-ops，装在作者本机的 C:\Users\ds245\.workbuddy\skills\，不在项目里，不能随项目走
部署脚本deploy\deploy.bat 是从检查工具复制过来的，里面的仓库名、技能名还指向检查工具，直接跑会装错东西，目前没有对外可用的一键部署

一句话：能用，但还搬不到别人电脑上——换台机器得人工把上面三样重新配一遍， 还得知道路径怎么填、技能放哪。这就是"还没做迁移化重构"的具体含义。

3.2 重构之后会是什么样（照检查工具的流程抄）

检查工具已经做完这一步，它的做法是：新建一个空文件夹 → 跑一条命令 → 把打印出来的两段配置接进 AI 工具。 生成工具照抄同一套，重构后的差别是：

项目现在（重构前）重构后（照检查工具的流程）
装服务手工填路径、手工改配置一条命令：curl -L -o deploy.bat <脚本地址> && deploy.bat
装依赖手工装 Python 环境和依赖包脚本自动装（缺 uv / git 会自己下载）
MCP 配置手工照着写一段 JSON脚本自动生成并打印，直接粘
技能从作者本机目录手工拷技能随项目走，脚本直接给出路径
换台电脑的成本得懂路径和目录结构，半小时起不懂也能装，几分钟
日常使用（说话）不变完全不变

重构只改"装"这一段，用法一个字都不用改——3.3 开始的操作流程，重构前后完全一样。

3.3 确认 Allegro 在跑

做什么：打开 Allegro PCB Editor（也可以直接让 AI 帮你启动，技能里有启动方法）。

看到什么就算成功：命令行 netstat -ano | findstr 7777 能看到端口在监听，或 AI 回你"通道已就绪"。

这一步必须做——封装只能在 Allegro 里面生成，工具的作用是"驱动它画"，不是替代它。

3.4 说一句话

做什么：在对话框里说（给规格书路径，或给装着规格书的文件夹）：

帮我根据这份规格书建立封装：<规格书路径>

看到什么就算成功：AI 自动跑完整个链路，回报"成功"，并列出产出的文件和归档位置。

它中间会自己干这些事（你不用管，但报告里能看到）：

阶段干什么
① 找尺寸页在规格书里定位"推荐焊盘图"那一页，渲染出来读参数
② 离线对拍先算出几何并打印对拍表，每个数都要在规格书上有出处
③ 建模驱动 Allegro 建焊盘 → 放引脚 → 画丝印 → 画本体 → 画占位框 → 写位号 → 存盘
④ 编译编译出 .psm 成品
⑤ 验证编译日志 + 规则检查 + 回读复核，三重都对才算完
⑥ 归档三件套 + 规格书放进与封装同名的文件夹

★ 任何一步失败会立即停下并给出中文原因（如"缺位号"、"引脚编号重复"），不会硬着头皮画出一个半成品。

3.5 取出产物

做什么：到归档目录（规格书所在目录下、与封装同名的文件夹）取三件套。

看到什么就算成功：目录里 .dra + .psm + .pad 三样齐全，且 .pad 与 .dra 在同一目录。
