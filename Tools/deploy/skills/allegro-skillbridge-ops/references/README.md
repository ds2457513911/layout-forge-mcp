## 这个目录是干什么的

装 `allegro-skillbridge-ops` 的**详细知识**。`SKILL.md` 只留「入口 + 红线 + 收尾铁律 + 索引」，
其余全部下放到这里，靠**按需读取**避免每次触发都吞掉几万 token。

拆分原则：**只剪切，不改字**。原章节的文字一字未动地搬进来，
只有两处有意改动：每个文件加了头部说明、多章节文件在接缝处各插了一个空行。

## 关键约定与坑

1. **章节号是原文编号，不要重排、不要重编号**。
   正文里的「见第十一节」「5.4.1 / 5.4.2 / 5.4.3 / 5.4.4」都指向原编号，
   重编号会把所有交叉引用打断。`SKILL.md` 第 5 节有对照表。

2. **多章节文件里，章节按原文行序排列**（不是按重要性）。
   例如 `lifecycle.md` 的顺序是 二 → 十 → 十一 → 十四。

3. **文件头部的 `> 收录原 …` 行要跟着改**：如果以后往某个文件里补了章节，记得同步头部。

4. **加新内容前先想"该进哪个文件"**。★ 2026-10-09 更正本条的理由 ——
   **文件数量本身不影响上下文**（官方规范：bundled resources 是
   `As needed (unlimited)`，`references/` 只在被读到时才进上下文）。
   真正会变贵的只有三条：
   - **索引行常驻**：SKILL.md 第 5 节每加一行 ≈ **112 字符**，而 body 是
     **触发即全量载入**的。这是唯一真实的 token 成本（目前 8 行 ≈ 900 字符）。
   - **路由歧义**：文件越多越难一眼指对，指错就读错文件、或连读两三个，
     把省下的量又吃回去 —— 这条比索引行贵得多。
   - **grep 关键词撞车**：关键词重叠 → 一次命中多个文件 → 都读。
     所以每条索引的 grep 关键词要**互相排他**。

   结论：**别设文件数上限，要设「索引行 + 关键词」的预算**。
   拆分的判据是"会不会一起被读"——不会一起读的就该分开，
   总是一起读的就该合并。（2026-10-09 新增 `mcp-tools.md` 即按此判据批准。）

5. **代码块内以 `#` 开头的行保持原样**。
   例如 `lifecycle.md` 里的 `# Allegro advisory lock file` 是 `.lck` 文件的内容，
   不是注释。要按标题机械切分时，先让工具识别 ``` 围栏。

6. **不要把 `README.md`（本文件）加进 SKILL.md 的索引表** —— 它是维护者文档，
   加进去就等于每次触发都读一遍，纯浪费。
