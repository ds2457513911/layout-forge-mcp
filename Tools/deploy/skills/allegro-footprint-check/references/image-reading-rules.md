# 读图提取规则（datasheet → theoretical_payload）

> 从 SKILL.md 剥出（原「第 3 步」的提取规则 / 公差规则 / 输出格式 / unconsumed / SHAPE 小节）。
> **每次要读规格书数字之前读**：这是"读得对"的判据来源，不是可选项。

#### 提取规则

- **★ 分辨率铁律（2026-09-29 实测踩中）**：**禁止用整页低分辨率图读数字**。
  实测同一份规格书（3S48000163 p5 LAND PATTERN）：
  - 200 dpi 整页渲染 → 把纵向间隙 `0.5` 读成了 `0.7`（**读错**）
  - 450 dpi **区域裁剪放大** → 读对 `1.2 | 0.5 | 1.2`
  正确做法：先定位区域 → 用 MCP 工具 `render_pdf_region(pdf_file_path, page, rect, dpi)` **裁到该区域 + 提高 dpi（≥400）** → 再读数。
  （旧写法"用 PyMuPDF `clip`"已废止：手写解析与禁止条 5 冲突，且 `render_pdf_page` 固定 150 dpi、做不到区域裁剪。）
- **★ 读数顺序（2026-11-19 起，按这个走，别跳步）**：
  1. `pdf_probe` 判形态 → `locate_land_pattern_page` 定页；
  2. `extract_page_numbers(pdf, page)` 拿**带坐标**的候选数字 —— 数字最密的一块就是标注区，
     这一步是「该看哪」的依据，**不是**读数本身；
  3. `render_focus_regions(pdf, page)` 拿概览图 + 焦点图（dpi 由像素配额反解，焦点区 ≥600 dpi，
     做不到就 2×2 切块而不是降 dpi）。读哪张就写哪张：**页码 + 图 id（overview/focus…）**；
     要指定区域再用 `render_pdf_region`；
  4. `reconstruct_pad_array(pdf, page)` 拿矢量候选（pad / pitch / 行列 / 本体），与读图值对拍；
  5. `measure_region` 再做一次几何交叉校验。三路不吻合 → **停下问用户**，不要挑一个顺眼的。
- **★ 证据里写工具返回的实际 dpi，不是你请求的 dpi**：视觉接口有**单边 8192 像素**硬上限，
  `render_pdf_region(..., dpi=1200)` 遇到整页 A4 会被静默夹到 ~700 dpi。返回值里的 dpi 才是这次
  实际看到的分辨率，写进证据；请求值和返回值不一致时不要按请求值自我安慰。
- **★ 矩形太宽一样会失败（400 unsupported image）**：上限卡的是**单边长度**，不是总面积/字节数。
  实测 8300×2000、9000×1500、9322×3175（446 KB）都报 400。要细看就**拆成窄矩形分次渲染**，
  别把两块拼成一张超宽图。
- **★ 一次只产一小段结论，别憋一份大 JSON（教训来自 #32 / #34）**：
  ① 整份大 JSON 被 `max_tokens` 截断就**整例作废**（实测思考就吃掉 15k–16k token，正文还没开始）；
  ② evidence 里抄原文（尤其带引号/括号的表头）会把 JSON 弄坏。
  所以：每轮写 1–3 个字段 + 一句依据（**≤60 字，只写数字与视图**），逐段推进。
  括号里的数（如 `(0.5)`）通常是参考值/公差，**不是新尺寸**，不要当另一个字段的值。
- **★ 交叉校验（读完之后必做，至少两条）**：
  1. **图纸内自洽**：相邻标注求和是否等于总尺寸（如 `1.2 + 0.5 + 1.2` 应等于标注的总高）
  2. **与既有产物比对**：同名件若已有 `.dra` / 历史检查报告（★ 2026-10-16 起报告统一归档在 `<封装目录>/check_log/`，历史报告见项目 `Tools/log/`），用它的实测值反查本次读数
  3. 只有"数值范围守门"（0.2~5 mm）**挡不住** 0.5↔0.7 这类量级相近的误读，别拿它当保险
- 图片可能旋转 90 度，先在心里旋转再读数
- 只读 **land pattern / recommended pad / 推荐焊盘** 区域，不读器件外形尺寸
- 区分"器件尺寸"（3.2×2.5 是器件本体）和"焊盘尺寸"（1.4×1.2 是铜箔）——**只要焊盘尺寸**
- pin 号必须是整数，不要输出 "1" 或 1.0
- 单位统一 mm；mil 换算：1 mil = 0.0254 mm
- spacing_x / spacing_y 是焊盘中心间距，无标注填 null
- 数值合理性自检：单个焊盘通常 0.2~5mm；小于 0.1 或大于 10 肯定误读
- 图纸模糊 → note 里说明，不编造

#### 公差提取规则

- 图纸写 `0.30±0.03` → tolerance = `{"min": -0.03, "max": 0.03}`
- 图纸写 `0.30 +0.03/-0.01` → tolerance = `{"min": -0.01, "max": 0.03}`
- 图纸只写名义值（如 `1.4`）→ 该维度 tolerance 填 null
- 公差区域模糊 → 填 null，note 里说明
- **图纸没标公差 ≠ 数据不可用**，正常提取名义值

#### 输出格式

    {
      "unit": "mm",
      "pads": [{"pin": 1, "width": 1.4, "height": 1.2}],
      "spacing_x": 2.2,
      "spacing_y": 1.7,
      "tolerance": {
        "width":     {"min": -0.03, "max": 0.03},
        "height":    {"min": -0.03, "max": 0.03},
        "spacing_x": {"min": -0.05, "max": 0.05},
        "spacing_y": null
      },
      "unconsumed": [],
      "note": ""
    }

**★ `unconsumed`（spec 守卫，2026-10-13 起）**：规格书里看到、但上面
schema 没有字段承载的约束（如安装扭矩、平面度、非常规公差基准、
特殊镀层要求），**必须**逐条声明在这里（`{"item": 名称, "value": 值,
"note": 说明}`），禁止静默丢弃。`validate_land_pattern_json` 会校验格式，
检查器把每条作为 WARN 打进报告（0.1 spec 守卫）供工程师裁定——
忽略可以，忽略而不告诉你不行。没有就留空数组。

**★ SHAPE 型焊盘（0.2 显名，2026-10-13 建模）**：读图或 extracta 里
`figure_name='SHAPE'` 的焊盘是**自绘轮廓**（如开口焊盘
JOPEN25X30_S-L-P），工具只拿得到包围盒、轮廓几何未建模——检查器
自动出 0.2 WARN，报告解读时这类件的形状类目测项（轮廓与规格书
一致性）必须提示人工复核，不得宣称"形状已验证"。喂
`solve_footprint_geometry` 的 spec 也不接受未知键（builder 未知键
守卫会 WARN 显名）。
