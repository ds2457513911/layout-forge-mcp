## 2. 读图链路（可复现）

### 2.1 ★ 图纸比例必须先解出来，否则任何 pt 坐标都不能当毫米用

标题栏 `SCALE: 1:1` **是假的**。用尺寸线两端箭头反推：`get_drawings()` 里 53 个实心图元全是箭头（水平箭头恒 `w=6.96 pt`、竖直箭头恒 `w=2.28 pt`，箭头中心到尖端恒 3.48 pt）。

| 标注 | 两箭头外端点跨度 | 算得比例 |
|--|--|--|
| 4.85 | 51.96 pt | 3.7795 |
| 4.25 | 45.46 pt | 3.7735 |
| 3.43 | 36.76 pt | 3.7808 |
| 3.35 | 35.86 pt | 3.7763 |

均值 **3.7775 : 1** → 换算常数 **mm = 显示 pt × 0.093413**（display pt = `page.rect` 841.89×595.276 的已旋转坐标；page 有 `/Rotate 270`，`get_text('words')` 与 `get_drawings()` 给的是未旋转坐标，等价换算 `display_x = raw_y`、`display_y = 595.276 − raw_x`）。

同一常数被随后的尺寸串交叉验证：`5-0.60`→0.598、`5-1.20`→1.199、`3-2.20`→2.200、`3-1.60`→1.603、`2.40`→2.406（mm），全部吻合。

## 4. ★ 不确定项与理由（本案例最大的一块：本体口径）

图内对同一本体给出**三套不一致**的宽度/长度，逐段矢量实测（基线：本体上边缘 y=94.88，中心线 x=644.04；mm = 0.093413 × pt）：

| 口径 | 本体宽（x） | 本体长（y） | 依据（逐段实测） |
|--|--|--|--|
| ① 主箱体 | **6.78** = 3.43 + 3.35 | **12.00**（左下侧视图标注） | 边缘线 x=607.32 与 x=679.92，72.60 pt = 6.781 mm |
| ② 外接总尺寸 | **7.60** = 3.95 + 3.65 | **12.196** | 轮廓 601.80..683.04 = 81.24 pt = 7.589（601.80 = R0.70 拨杆凸出部，683.04 = 右下方阶）；长度 94.88..225.44 = 130.56 pt = 12.196 |
| ③ 俯视图顶面 | **6.70 ± 0.10** | **11.60** | 左上俯视图标注 `6.70±0.10` 与 `11.60` |
| .dra（人做封装） | **6.7805** | **12.0000** | `ASSEMBLY_TOP` 本体轮廓 bbox |

**本次取 ①（6.78 × 12.00）**，理由：(a) 与 .dra 那张人做封装自量的本体轮廓逐位吻合（差 0.0005 / 0.0000），而同套件既有件 `lydpj_5p_12x6` 的口径裁定正是拿 .dra 的 `ASSEMBLY_TOP / SILKSCREEN_TOP` 轮廓来定本体；(b) 两个数都是图上**有独立标注**的量（`3.43`/`3.35`/`12.00`），可引可查；(c) ② 是把开关拨杆凸出部也框进去的外接尺寸，③ 是顶面尺寸，都不是「本体主箱体」。

**必须说清的是**：历史候选 `knowledge/specs/nb_cstj421_aj35_6p.json` 的 `body_x=7.59 / body_y=12.2` 就是口径 ②，而它自己也写了已知不确定项「本体轮廓做成外接矩形（含左侧 R0.70 凸出部）；图上其实是阶梯形」。本次**没有偷偷改历史值**，两套值都留在这里，请人工签字裁定。若最终裁定为 ②，则 `body_x/body_y` 改 7.59 / 12.20，此时 .dra 的 `body_x`（6.7805）会变成 **disagree**。

### 4.1 关于 `.dra` 文件名 `nb_audio6_12x7d25x4d3` 与 body 的关系（用户点名的核对项）

名字里的 `12 / 7.25 / 4.3` 与**任何**一套本体口径都不完全对得上：

- `12` 最接近本体长度（12.00 / 12.20）；
- `4.3` 接近左下侧视图的本体高度 `4.20±0.10`；
- `7.25` 正好等于**中视图（正视插孔那张）的竖向标注 7.25** —— 那是插孔部的高度，**不是本体宽度**。

也就是说这个名字是「长 × 高 × 厚」的器件口径，不是封装坐标 X/Y 口径；而且本项目其它 .dra 名同样对不上自己的封装（`lydpj`：名 `13.05×6.3×4.2`，实测本体 12.2×6.7、侧视高 4.2；`tf9`：名 `16.19` 写在第二个数而 `body_x=16.19`）。**因此文件名不构成本体读数的证据**，也不能用来推翻 `3.43+3.35` / `12.00` 这两处图上直接标注。

### 4.2 ★ 历史 spec 声称的「RECOMMEND PCB LAYOUT」视图在 PDF 里找不到证据

两页全文搜 `RECOMMEND / PCB / LAYOUT / SUGGEST / DRILL / HOLE / PAD` → **0 命中**；渲染出的整页图上也没有这个标题。第 1 页实际是 4 个正交视图 + 插头图 + 轴测图 + 零件表 + NOTES + 标题栏，**右侧那张（底面视图）是唯一画出焊盘/引脚位置与编号的图**，自带完整尺寸串但没有标题。本报告因此以「右视图」指代它，并把它当作规格书的 land pattern 依据。`nb_cstj421_aj35_6p.json` 里那句「右上角 RECOMMEND PCB LAYOUT 视图」属**无文本层证据**的表述，签字时请留意。

### 4.3 历史候选 `pitch_x=1.76 / pitch_y=1.0` 在图上和 .dra 里都找不到对应量

- `1.76` ≈ 3.95 − 2.19，象是把某个焊盘尺寸混进了间距；
- `1.0` 与 `2-2.00` 有关（2.00 是 **5/6 号脚的焊盘长**标注，也不是脚距；5 与 6 的实际 y 差是 2.60）。

本次判 `null` 不是「没读到」：6 个脚的位置已由 PDF 矢量焊盘中心与 .dra 引脚坐标两套证据逐点对上（§2.2，≤0.02 mm），相邻脚间距五档/四档互不相等。

### 4.4 坐标轴口径（防「按较长边转置」）

canonical 的 `body_x/body_y` 按**封装坐标帧**取值（`services/geometry_solver.py:1070-1073` 用 `body.x/body.y` 作居中矩形半宽；`services/spec_library.py:131-132` 直接把 `body.x→body_x`、`body.y→body_y`）。本件长边在 **Y**：.dra 的 `PLACE_BOUND` y 向 13.31 > x 向 11.51，`ASSEMBLY_TOP` 中心线沿 y 走 12.2。故 `body_y = 12.00`（长）、`body_x = 6.78`（宽），**不要**按「body_x 是较长边」的直觉转置。
