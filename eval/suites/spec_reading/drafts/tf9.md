## 0. 读法顺序（纪律声明）

1. **第一步：只看 PDF 定读数。** 用 pymupdf 探形态 → 横向整页 300dpi 拼图定位 → 对 page 1 的俯视图与 PCB 图形区按**未旋转坐标**做区域高 dpi 裁切 → 目视读图注、引脚编号、Assignment 表。
2. **第二步：读数定稿后才读 .dra** 做交叉核对。
3. `candidates/tf9.json` 里的 8 个值**全部来自第一步的 PDF 读数**，没有任何一个字段是"看了 .dra 之后回填"的。本报告下方所有 .dra 数字都属于第二步的事后核对。

> ⚠️ 页为 `/Rotate 270`：未旋转页面 595×842（纵向），横向渲染 842×595。读数时必须按未旋转坐标裁图（`x_u = 595 − y_r`，`y_u = x_r`）。过程中曾因两套坐标混用产生误读，已全部重测修正；下表所有引文来自修正后的渲染图。

## 1. 8 个 canonical 字段（证据表）

| 字段 | 值 | 页码 | 引文（图上标注串） | 怎么量的 |
|--|--|--|--|--|

**判轴依据（pitch_x 与 body_x 同轴的关键推理）**：俯视图里 `⑭ 16.19` 是**图上横向**尺寸，而 9 个引脚编号 `1…8 cd` 与焊盘列**同样沿图上横向**排布 —— 引脚排布轴 = 16.19 那一轴。故 `pitch_x`（引脚排布轴间距）对应 16.19，`pad_x` 取引脚排布轴方向的焊盘宽 0.70（垂直方向为 1.60）。

## 2. .dra 交叉核对

用 `services.extracta_reader.read_via_extracta`（**unconfined python 3.10.11** 驱动 Cadence extracta 四视图）读出 pins/layers/texts/units 等，取每个 pin 的 `xy` / `bbox` / `size` / padstack 名。比对时把 .dra 的 x 轴（引脚排布轴，间距 1.10）对齐到 PDF 的引脚排布轴（16.19 那一轴）。

### 2.1 逐字段对照

| 字段 | PDF 读数 | .dra 推出 | 结论 |
|--|--|--|--|
| mount | smd | smd（全部 pad 只有 `ETCH/TOP` + `SOLDERMASK_TOP` + `PASTEMASK_TOP`，**无 DRILL**；唯一带 DRILL 的是 NPC 定位柱） | ✅ 一致 |
| pin_count | 9 | 9（pin `1`…`9`） | ✅ 一致 |
| pitch_x | 1.10 | 1.10（pin1..9 的 x = 12.1, 11.0, 9.9, 8.8, 7.7, 6.6, 5.5, 4.4, 3.3，**恒差 1.10**） | ✅ 一致 |
| pitch_y | null（单排，不适用） | null（同样只有单排） | ✅ 一致 |
| body_x | 16.19 | 16.19（全部 pin 的 x 跨度 17.5，含安装柱外伸；长轴） | ✅ 一致 |
| body_y | 14.50 | 14.50（全部 pin 的 y 跨度 13.46；短轴） | ✅ 一致 |
| pad_x | 0.70 | 0.70（padstack 名 `R1D6X0D7`，bbox `size [0.7, 1.6]`） | ✅ 一致 |
| pad_y | 1.60 | 1.60（同上） | ✅ 一致 |

**agree = 全部 8 个字段；disagree = 无。**

### 2.2 两边各是什么 / 口径差异（不计入 disagree）

| 观察项 | PDF 口径 | .dra 口径 | 说明 |
|--|--|--|--|
| 本体轮廓 | **16.19 × 14.50**（规格书本体轮廓/最大长宽） | `PACKAGE GEOMETRY/SILKSCREEN_TOP` 外框 **19.23 × 17.38** | .dra 丝印比 PDF 本体各大约 1.5–3 mm。**两边口径不同**（丝印外框含法兰/卡口外扩 vs 规格书本体内腔轮廓），不是冲突，故写成观察项而非 disagree。人签字时若要统一口径需自行决定 body_x/body_y 采哪一边 |
| 焊盘总数 | 9 信号 + **4 个外壳大焊盘**（1.60×1.50 与 1.20×2.20 的尺寸注在图上，但**位置未标注**） | **15 pad**：9 信号 + pin10 `R1D5X1D2`、pin11 `R1D6X1D5`、pin12/pin13 `R2D2X1D2`（4 个外壳脚）+ pin14/pin15 `NPC1`（2 个定位柱） | 4 个外壳脚在 PDF 只给尺寸不给位置，故不对它们做逐字段比对 |

### 2.3 倾向

8 个字段两边**完全一致**，无需在冲突中取舍。唯一需要人裁决的是 §2.2 的**本体轮廓口径**（16.19×14.50 vs 丝印 19.23×17.38）：本草稿按规格书口径填 16.19 / 14.50，因为 canonical 字段语义是"器件本体长/宽"，而规格书本体轮廓正是这个语义。

## 3. 不确定项与理由

1. **pad_x / pad_y 的口径（中风险，建议人工确认）**
   图形区里有两个"0.70"：一个在信号焊盘阵列右端（焊盘宽），一个在下方外壳大焊盘旁（图形区右下 `0.70`）。同时外壳大焊盘标 `1.60 / 1.50`。本稿取 **信号焊盘 0.70（排布轴方向宽）× 1.60（高）** 作为 pad_x / pad_y，理由：
   - .dra 里 9 个信号 pin 的 padstack `R1D6X0D7` 明确是 **0.7 × 1.6**，且 .dra 的 x 轴（=1.10 间距轴）上焊盘尺寸正是 0.7；
   - 8-1.10 的 `1.10` 是**中心距**（8 段 × 1.10 = 8.80 = `⑥ 8.80`），而信号焊盘阵列的 0.70 是**焊盘宽**，两者不混；
   - 4 个外壳大焊盘尺寸（1.60×1.50 / 1.20×2.20）与信号盘不同，按 canonical 语义"规格书推荐焊盘宽/高"取信号脚常规焊盘。
2. **pitch_y = null 的语义（低风险）**
   9 脚排单行，y 向无相邻引脚对 → 结构性"不适用"。按任务书"无规则间距/不适用 → 值写 null 并给 null_reason"处理，**不列入 unreadable**。
3. **body_x / body_y 的轴向（已解决，低风险）**
   通过"9 个引脚编号沿图上横向 → 引脚排布轴 = `⑭ 16.19` 一轴"定轴，并与 .dra 的长短轴归属互相印证（.dra 长轴 17.5 含安装柱 / 短轴 13.46）。置信 high。
4. **PDF 文字层缺失（已处理）**
   `page.get_text()` 提不到 `16.19` / `8-1.10` / `0.70` 等（尺寸为矢量轮廓）。因此本报告引文全部来自高 dpi 渲染图上的标注串，而非文本层原文；这不是读数缺陷，是 cad_vector 形态的固有属性。
5. **pitch_x 的图上依据（低风险）**
   `8-1.10` 直接用"8-1.10"格式表达"8 段、每段 1.10"，与 `⑥ 8.80` 完全自洽（8×1.10=8.80），且被 .dra 的恒差 1.10 独立证实。置信 high。
