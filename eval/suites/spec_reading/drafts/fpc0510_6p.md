**disagree = 1 项**：`pin_count`

### `pin_count` 冲突说明（不许偷偷改读数，两边都留）

- **PDF 值 = 6**：规格书标题 `FPC 0510-6P`，CKT 表 `6` 行，RCB LAYOUT 上恰好 **6 个信号焊盘**（`B=2.50=5×0.5`）。
  此外图上另有 **2 个固定脚焊盘**（`0.30±0.03 × 1.15`，位于本体下方两侧，与信号排错开 1.91）。
- **`.dra` 值 = 8**：人做的封装把 **6 信号脚 + 2 固定脚** 一起建模为 8 个 pin，用了两种 padstack。
- **我的倾向**：canonical 字段 `pin_count` 定义为「信号引脚数（外壳脚/定位柱不计）」，本案例**应取 6**；
  8 是「含固定脚的物理焊盘总数」，属于另一个口径。**本报告不修改任何一边的读数**，两值共存待人工裁决。
- 参考材料里的既有 spec `knowledge/specs/nb_fpc0510_6p_4d77x3d6.json` 记的是 `pin_count: 8`，其 `notes` 亦自述「8 是『6 信号 + 2 固定』」——与本判断同源，但**该文件未被用作任何读数来源**，仅在此对照段列出。

## 4. 不确定项与理由

### 4.1 `pitch_y = null`（已判 null，附理由）

- 器件只有**单排**信号脚（`rows=1`，6 个信号脚 `y` 全为 `-2.235`），y 方向不存在相邻引脚。
- 固定脚 7/8 共用一个 `y=0.575`，与信号排的 y 差 2.81mm（来自 `.dra`），**规格书上没有任何标注**表明这是 pitch。
- 结论：`null` + `null_reason`。若签字方希望 `pitch_y` 改表示「信号排↔固定脚排 y 向距离」，其值为 **2.81mm**（仅 `.dra` 有据，PDF 无据），本报告不据此填值。

### 4.2 `pin_count` 口径（medium 置信度）

数值 `6` 本身可靠（标题 `6P` + CKT 表 `6` 行 + 图上 6 个信号盘，三重印证），
但「canonical `pin_count` 到底数信号脚还是数全部焊盘」这一**口径**需人工确认，故该字段给 `medium`。

### 4.3 `body_x` / `body_y` 的轴向归属（已交叉验证，倾向 high）

规格书**没有 x/y 轴定义**，只有 A/B/C/D 标记。本报告按 canonical 口径取
「`body_x` 沿焊盘排列方向 / `body_y` 垂直方向」，依据：

1. `.dra` 的 `ASSEMBLY_TOP` 本体矩形 `size = [4.77, 3.6]` —— 与 `A=4.77`、`C=3.60` 同轴；
2. `.dra` 中 4.77 这一轴正好容纳整个焊盘排（信号脚 x 跨度 ±1.25，固定脚 x ±2.135；而 y 方向 3.6 轴放不下 ±2.135，放不下的轴向必然不是 3.6 轴）；
3. 两轴互换会得到 `[3.6, 4.77]`，与 `.dra` 本体矩形直接矛盾。

→ 结论：`body_x=4.77` / `body_y=3.6`，PDF 与 `.dra` 互相印证，判 high。

### 4.4 未使用的尺寸（避免与 canonical 字段混淆）

信号排上缘→本体下缘 `1.91`；信号盘下缘到固定脚上缘；固定脚盘 `0.30±0.03 × 1.15`；
`(0.25)`、`(0.11)`、`(1.135)`、`(B+1.0)±0.05 = 3.50`、`(2.32±0.15)`、`(1.25)`；
本体高 `2.90`（H1.0 公称）；端视图 `3.35±0.15`、`0.55±0.15`、`1.00±0.15`；
Applicable FPC 的 `4.00 MIN` / `3.00 MIN`。这些都不属于 8 个 canonical 字段。
