### 读数过程中的关键弯路（说明为什么最终敢下这些值）

最初只看光栅像素时，同一排相邻脚测得约 3.0 mm（约 2.4 倍），与图上打印的 `1.00` / `1.50` 明显矛盾。原因有二，均已排除：

1. `render_region` 的 y 是**自上而下**（y-down），早期用 y-up 假设定位，一直渲染到错误的视图（渲染出的是 PIN 表与标题栏而非推荐 layout），导致把表格里的线段当成焊盘行。
2. 早期按「请求 dpi」推算 mm/px，而实际 PNG 像素数与该推算不自洽（该 dpi 被上限截到 1200/做了重采样），比例整体偏了约 2.4 倍。

改法：**用图上的打印尺寸本身当标尺**（`1.00` 的延伸线间距、`Ø0.55` 孔）反标定比例，再重测；随后用同图号 DXF（真实 mm）做几何复核，两者一致才落值。

## 3. 不确定项与理由

1. **`pad_x`/`pad_y` 的口径（最需要人确认的一项）**
   推荐 layout 里有两组焊盘尺寸：
   - 信号脚：`Ø0.85`（圆盘，配 `Ø0.55` 孔）→ 本真值采用
   - 外壳脚/安装槽：打印簇 `0.77` × `1.38`
   本真值把 `pad_x=pad_y=0.85` 理解为「规格书推荐焊盘」的信号脚圆盘直径（与 .dra 的 `PC0D55HC0D85 = 0.85×0.85` 一致）。**若项目口径是「最大焊盘」或「外壳安装槽」，应改判为 `0.77` / `1.38`。** 两个值都留在此处，未偷偷改读数。

2. **`pitch_x` / `pitch_y` 的方向命名**
   图上直接标注的是 `1.00`（同排相邻脚）与 `1.50`（两排之间）。本真值取 `pitch_x=1.00`、`pitch_y=1.50`（与 .dra 坐标系一致：.dra 的 x 步进 1.0、两排 y 差 1.5）。若评测口径把「引脚阵列长轴」定义为 y，则两者需对调——数值集合不变，仅命名互换。

3. **`15.50` 与 `18.50` 的含义**
   这两个打印尺寸出现在推荐 layout 里。按 .dra 复核，外壳脚 x 间距分别为 **14.5**（上排）与 **18.5**（下排），而信号脚阵列（19 脚）两端中心距为 **18.0**。因此 `18.50` 最可能对应外壳脚最外一组间距（.dra 下排 18.5 精确吻合）；`15.50` 与 .dra 的 14.5 未完全吻合，其归属（外壳脚上排 / 信号脚最外脚中心距 / 板边）**未完全确定**，故未把它用作任何 canonical 字段。此项不影响 8 个字段的取值。

4. **`body_x` / `body_y` 的层级**
   PDF 打印 `15.00` / `12.50` 为本体口径，与 .dra 文件名 `15x12d5` 一致。`.dra` 的 `PLACE_BOUND_TOP` 是 `25.03 × 13.76`（含端子伸出/摆放余量），**不是**本体尺寸，未采用。

5. **`render_region` 行为**（对后续读图有影响）
   该函数的 y 参数是 **y-down（自上而下）**；且请求 dpi 有上限（请求 1600 实际落到 1200），**不能拿「请求 dpi」直接当 mm/px 标尺**。建议后续读数一律用「图上打印尺寸」或已知特征反标定比例。
