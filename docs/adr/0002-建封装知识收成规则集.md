# ADR-0002 建封装知识收成规则集：一份数据、两个方向

把「这一类封装该长什么样」从代码里的分支搬进一份可读、可版本化的规则集；同一份数据同时供**派生**（建）与**判定**（查）两个方向使用。

- **Status**：Accepted（2026-11-20）
- **背景**：建封装侧的约定散在两处——`services/convention_engine.py` 只管通孔长圆孔（`apply_conventions`），`services/geometry_solver.py` 的 `solve_padstack` 里又写死了阻焊 0.05、钢网等于焊盘、命名规则；判定侧另有 `services/rule_checker.py` 的 2.7/2.8/2.9/2.10 各写一遍同样的知识，阈值再拆到 `knowledge/rules/checker_rules.json`（27 个键，判定逻辑仍在代码）。按 `knowledge/conventions.json` 的 `used_count` 统计，全库 415 个 padstack 里 **SMD 占 359（86%）零规则**，已接的只有通孔长圆孔 26 个（6%）。结果：同一份知识三处各写一份，靠纪律维持同源；换一种形态就要改代码。
- **目标**：让「该长什么样」（派生）与「对不对」（判定）**读同一份数据**，并且这份数据可版本化、可对拍、可解释每个值从哪来。

## 决策

### D1 四类对象

规则集由四类对象组成，各有独立 id：

- **form**：形态。谓词组合（层存在、层集包含、孔形匹配、名字族、安装方式），谓词白名单内置在引擎里，白名单之外不执行。每个 form 有 id，写进报告。
- **parameter**：参数。数字只写一次，派生与判定都引用它。
- **rule**：规则。挂在 form 上，可以只有一侧（见 D2）。
- **source**：出处。指向挖出该值的语料与文件（如 `conventions.json#adjudicated.th_oblong_plated.mask_expand_side_mm`）。

「约定」一词退出字段层，只作规则集的人读叫法。form 独立成对象的理由是：输入匹配不上任何 form 时，必须能给出**可解释的 SKIP**，而不是静默无规则。

### D2 规则的字段与双向

每条规则字段：`id / form / when / use / derive / assert / severity / source / since`。

- `derive` 是正向：形态命中后，用参数把读数展开成 padstack 定义（层集、各层尺寸、命名、旋转）。
- `assert` 是反向：形态命中后，用参数判定给定 padstack 合不合格。
- 两侧共用同一批参数；允许只有一侧（间距这类只有判定、没有派生值）。**只有 assert 侧的规则在 derive 模式报 SKIP 并注明「该形态缺派生规则」**，不静默跳过。

### D3 引擎三态

判定输出三态：**满足 / 违反 / SKIP**。SKIP 必须写明缺哪一条（缺 form、缺规则、缺参数、输入字段 UNKNOWN），不能只给空结果。

### D4 参数三样，按 form 分组

参数对象含：`value`（派生用的单值）、`allowed`（判定合格区间）、`warn`（警告带）、`support`（语料件数）、`source`。同一个参数按 form 分组给不同值，不是两个真源。

典型例子是阻焊外扩：通孔长圆孔组 `value=0.05`（22 件支撑），SMD 组 `value=0.08`（全量 195/246 个焊盘的惯例口径），两组 `allowed` 都是 `[0.05, 0.13]`。现在的两份数字（`conventions.json` 的 `mask_expand_side_mm` 与 `checker_rules.json` 的 `soldermask_expand_mm`）合并进这条参数的同一对象，判定侧的 2.2 改为引用它。

### D5 派生只管「长什么样」

derive 负责：层集（按 form 的层模板算出该有哪些层，不是固定六层）、各层尺寸（表达式引用参数）、命名（模板 + 占位符）、旋转（padstack 的本地帧方向）。

不负责「放在哪」——pin 坐标、阵列、原点、本体、Place_Bound、丝印、位号仍由 `services/geometry_solver.py` 计算。把几何求解搬进规则集，等于给规则语言加一套算术和坐标系，收益为零、维护两套求解路径。

### D6 命名与旋转的落法

命名模板声明在数据里（如 `POB{孔长}X{孔短}HOB{盘长}X{盘短}`），格式化生成器仍是一段代码；判定侧继续用**尺寸反推**比对，不解析模板——反推能抓「名字与尺寸不符」，比语法匹配更强。

旋转的决定在 derive（本地竖孔 + 板面横槽 → 该 padstack 引用到 pin 上必须转 90°），施加在 solver；判定侧读实际旋转值比对。

### D7 空缺分两类，只填一类

- **派生空缺**：书上没有、但由读到的数加规则唯一确定（层集、阻焊、钢网、命名、旋转）。derive 按规则填，每个值挂规则 id 与支持度。
- **事实空缺**：书上该有、但没读到/没印清（焊盘宽、引脚数、间距）。**谁都不能填**，报 UNKNOWN 并写明缺什么，回去重读或换来源；判定侧对 UNKNOWN 不得判 PASS。

这条线是防「把没读到当成按惯例应该是」的机制，2026-10 那轮误裁就是踩在这里。

### D8 三段职责固定

读数（人/模型，带页码与引文）→ derive（规则补全成 padstack）→ solve（把 padstack 摆成画布几何）→ builder（映射到宿主 API 建图）；assert 拿同一份读数与同一份参数反查实际产物。宿主 API 的映射（`axl*` 层名、属性）属粘合层，不数据化。

### D9 迁移与影子比对

- 新建 `knowledge/rules/*.json`；旧 `knowledge/rules/checker_rules.json` 冻结为 legacy 只读。
- 用迁移映射表逐键搬，可回滚；每条规则带 `since`。
- 规则库整体算内容哈希 `rule_set_hash`，报告同时记版本与哈希。
- shadow：对 253 件金标准逐条比 `items` 的 `id + status`，差异 0 才算过；有意改变逐条登记并附 ADR。

### D10 severity 由后果与证据量算

规则只声明 `consequence`（后果类型）与所需证据量，映射表放 `knowledge/rules/_severity.json`，引擎据此给 PASS/WARN/FAIL。理由：同一份「阻焊偏大」在通孔件与高密度 SMD 上后果不同，把 severity 写死在每条规则里会重复表达。

### D11 覆盖率是报告的一等公民

报告新增 `coverage` 段：form × 有/无规则。两类缺口都要列——**有形态但无规则**（form 命中、规则缺失）与**无形态**（输入连 form 都匹配不上）。前者来自「form 表 × 规则表」差集，后者只有运行时才知道；语料统计只标注每个形态多少件支撑，不决定清单。

### D12 晋升规则的两道闸

第一级案例即时记录；升成规则要同时满足：① 结构上可判定（字段或几何关系，不是「看图觉得」）；② 证据 ≥ 3 件同族，或 ≥ 2 个不同来源（其中至少 1 个是真实历史误判）。晋升要人签，且 253 件 diff=0、正反例进回归。现有规则支持度是 16/22/25/26 件，3 件是下限不是理想值。

### D13 派生侧的验收基准

derive 的输入是 spec，不是 `.dra`。验收以 `Tools/selfcheck_geometry.py` 的 239 项加 `knowledge/specs` 的 8 份 spec 逐字段相等为准；253 件只用于 assert 侧 shadow。用 `.dra` 对拍 derive 是概念错误——它们没有对应 spec，无法重跑派生。

## 被否方案

- **只做 assert**：单侧仍会与派生侧各写一份，双真源的问题原样保留。
- **继续扩 `convention_engine` 的分支**：形态 × 层 × 命名组合会让分支爆炸，SMD 359 件至今零规则就是证据。
- **把知识留成纯文档让模型现读**：不可对拍、不可版本化、每次结果依赖读的那一次。
- **让模型补全约定值**：书上没有的值模型只能编，且丢掉支持度与出处。
- **把 solver 搬进 DSL**：算术与坐标系不属于规则语言。
- **新库与 legacy 长期并存**：迟早分叉，必须有一次迁移收口。

## 后果与代价

- 需要写解释器（新模块）+ 迁移 24 条规则与 27 个阈值键。
- 迁移期代码里会同时存在 legacy 与新库，靠 shadow 与 `rule_set_hash` 兜底；收口前不许删 legacy。
- 报告字段变多（`rule_set_hash`、`coverage`、方向标签），下游解析要跟着改。
- **派生侧覆盖率天然窄**：253 件只能证 assert；derive 只有 239 项 + 8 份 spec，新形态的派生正确性在语料补齐前无人可证。这是已知风险，写进报告而不是藏起来。

## 何时重估

- SMD 规则大规模落地后，重估「层模板 + 表达式」的表达力是否够用。
- 规则数超过 100 条，或出现必须跨 form 组合的判定时，考虑引入受限表达式，而不是继续加谓词。
- 若宿主换成非 Allegro 目标，D8 的粘合层边界要重新划。
