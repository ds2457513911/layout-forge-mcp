## 三条改动手续

1. **新增 / 改名工具** → 改 `mcp_server/tools.py` → 补 `knowledge/tool_groups.json` 分组 → `--update` 冻结基线 → `--write-catalog` 重生成目录。别去改文档里的数字（文档里本来就不该有数字）。
2. **新增客户端（让某个 Agent 读到这份技能）** → 在落点声明里加一条 → 跑 `--verify-skills`，看它是 MATCH 还是 MISSING。落点不是猜出来的，是声明出来的。
3. **新增目录 / 模块** → 按 `LAYERS.md` 的登记手续走（README + 根 README 导航 + `REGISTERED_DIRS`）。本文件不重复那张表。

## 三条实证反模式（都真实发生过）

- **手抄数字会漏**：工具数从 36 到 39 时改了 12 个文件仍漏 11 处，随后一次「改成 39」又只改了五处中的两处 —— 所以「数量」只许出现在生成物里。
- **同一条规则会分裂成六份**：读数链曾有六种写法，扫描件兜底还指向被明令禁止的整页读数 —— 所以「顺序」只许有一份，其余留指针。
- **没有落点的检查会假绿**：九个落点全 `N/A`，末行仍打印「通过」并 exit 0 —— 所以 `N/A` 不算通过，零落点直接失败。
