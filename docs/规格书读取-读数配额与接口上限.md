# 读数配额与接口上限（2026-11-19 补）

> 这份笔记补的是《规格书读取方案》**档 1** 缺的两个参数：一块区域**多大**、图像**送出去能有多大**。
> 只讲"600–1200 dpi 区域裁剪"而不讲这两条，dpi 会纸上达标、实际白花——渲染出来的像素被模型压掉，或直接被接口拒。

---

## 1. 三组实测（2026-11-18，deepseek-flash 视觉通道）

### 1.1 接口卡的是**单边长度**

| 图尺寸 | 结果 |
|---|---|
| 8192×2000 / 7000×3000 / 6000×4000 | 通过 |
| 8300×2000 / 9000×1500 | 400 `unsupported image` |
| 9322×3175（仅 446 KB） | 400 `unsupported image` |

结论：卡单边，**不卡总像素、不卡文件字节数**；超限的图不会自动缩，接口直接拒。
→ 所以 dpi 必须**按矩形反解**，不能写死 1200：1200 dpi 下 500 pt 宽就是 8300+ 像素。

### 1.2 模型侧会把长边压到约 1600 px

900 dpi 的 A4 区域是 7442×8210 ≈ **6100 万像素**、约 20 MB PNG。模型内部压到长边 ~1600 px，
等效分辨率只剩 **~190 dpi**——正好落进本文档「200 dpi 把 0.5 读成 0.7」的翻车区间。
即：整块高 dpi 渲染，花的是自己的成本，丢的是自己的分辨率。

### 1.3 焦点区做不到 600 dpi 就**切块**，不降 dpi

一块区域切 2×2，每块面积 1/4，同样像素预算下能容纳的 dpi 翻倍。
当前实现：切块上限 4 块（`MAX_TILES = 4`），焦点区每块至少 600 dpi（`MIN_FOCUS_DPI = 600`）。

---

## 2. 三条规则（可实施）

| 规则 | 做法 | 状态 |
|---|---|---|
| R1 渲染前反解 dpi | `dpi = min(请求值, 1200, 8192 × 72 / 长边pt)` | ★ 已于 2026-11-19 落地：`services/pdf_service.py` 的 `dpi_for_max_side()`，`render_region` 内按 `clip` 实际尺寸二次夹取 |
| R2 送模型前按像素配额压 | 概览图长边压到 1600；焦点区要 600 dpi 起，做不到就切块 | ★ 已于 2026-11-19 落地：`services/pdf_reading.render_focus_regions`（layout-web 已归档） |
| R3 重渲也压 | 模型二次指定区域时，dpi 同样按 8192 反解；返回值里是**实际** dpi，写进证据 | 随 R1 自动生效 |

## 3. 参数表（改之前先看这张表）

| 名字 | 值 | 含义 |
|---|---|---|
| `MAX_SIDE_PX` | 8192 | 视觉接口单边像素硬上限（见 §1.1） |
| `MAX_IMAGE_PX` | 1600 | 送模型前压到的长边（见 §1.2） |
| `MIN_FOCUS_DPI` | 600 | 焦点区最低等效 dpi；达不到就切块 |
| `DEFAULT_REGION_DPI` | 900 | 区域渲染默认 dpi |
| `MAX_TILES` | 4 | 焦点区切块上限 |

## 4. 与《规格书读取方案》§7.3 的关系

§7.3 的增量 1（`render_pdf_region` 让"区域 + 高 dpi"可执行）落地时**只做了渲染，没做配额**。
本笔记是它的第 4 条增量：**加配额**。没有配额，增量 1 在大区域上会被接口拒、在整页上会被模型压成 190 dpi。

来源实现（layout-web，可对照读，不要求照搬结构）：
`app/extract/packet.py:382-441`（分辨率配额与切块）、`app/extract/packet.py:470-516`（单边上限与二次裁剪）。

## 5. 未决

- `1600 px` 是 deepseek-flash 的行为，**换模型必须重测**（换成多图/更大输入窗口时这条会变）。
- `8192` 是单边；若将来换到能收更大图的接口，R1 的上限要跟着改。
- 焦点区切 4 块是否够：目前只对"数字密集区"切 2×2，多视图页（俯视+侧视各一组尺寸）可能要按视图切。
