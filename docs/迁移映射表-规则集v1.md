## 三、回滚配方（可按步骤执行）

配方 `ROLLBACK-MASK-EXPAND` 适用于 PARAM-MASK-EXPAND, RULE-MASK-EXPAND。

1. `expand_parameter`：把 `PARAM-MASK-EXPAND` 展开成三个扁平单形态参数 PARAM-MASK-EXPAND-TH-OBLONG、PARAM-MASK-EXPAND-TH-CIRCLE、PARAM-MASK-EXPAND-SMD（每组的 form/value/support/source + 参数级 field/keys/allowed/eps/unit）。
2. `rewrite_rule`：把 `RULE-MASK-EXPAND` 的 `use` 改回 PARAM-MASK-EXPAND-TH-OBLONG、PARAM-MASK-EXPAND-TH-CIRCLE、PARAM-MASK-EXPAND-SMD。

验收口径：按配方展开后，同一批夹具的判定结果（status/form/support/source_ref）与合并后逐件相等；2.2 端到端汇总仍为 files 253 / judged 235 / diff 0。

注意：数据侧回滚只做上面两步；派生侧回滚=git revert 票 #19 的提交（convention_engine 重新从 conventions.json 取 mask_expand_side_mm）。

## 四、下次迁移怎么复用

1. **先登记再动手**：在台账 `entries` 里给要迁的旧键/旧规则写好 `target`（指向真实存在的参数或规则 id），`status` 先留 `legacy`。
2. **迁移后改行**：真正接上以后把该行 `status` 改成 `migrated`，`rollback` 换成可执行配方（没有配方就只能写「未动」，R6.13 会对 `migrated` 行要求非空 `rollback`）。
3. **重渲染**：`python Tools/render_migration_table.py`，再跑 R6.13 闸门；旧键集合与旧规则 id 集合必须与源码里实际存在的完全相等——多一条漏一条都红。
4. **回滚演练**：`R6.14` 会照 `rollback_recipe` 把库展开回旧形态，用同一批夹具重判，结果必须与合并后逐件一致（`eval/baselines/rule_engine.json` 与 `eval/baselines/shadow_2_2_253.json`）。
5. **派生侧**：映射表只管数据；若迁移同时改了派生取值来源（如本次 convention_engine），回滚=连代码一起 revert，并在台账 `rollback_recipe.note` 里写明。
